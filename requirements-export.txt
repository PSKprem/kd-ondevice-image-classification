# P25 - ONNX / TFLite EXPORT environment (separate from requirements.txt).
# VERIFIED on Windows, Python 3.12, 25 Oct 2026 (w1.0 student: FP32 tflite == PyTorch predictions on 1000 test images).
#
# Why separate: this stack needs numpy 2.2 + TensorFlow 2.21, the training env must stay untouched.
#
#   py -3.12 -m venv D:\kd-project\.venv-export
#   D:\kd-project\.venv-export\Scripts\Activate.ps1
#   pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu
#   pip install -r requirements-export.txt
#
# Pipeline (see scripts/):
#   export.py --onnx-only      PyTorch checkpoint -> model.onnx
#   onnx2tf -i model.onnx -o <dir> -b 1          -> <dir>/model_float32.tflite  (default "flatbuffer_direct" backend)
#   quantize_tflite.py         FP32 .tflite -> INT8 (dynamic or static) with ai-edge-quantizer
#   eval_tflite.py             accuracy of a .tflite on the test set (+ agreement with PyTorch)
#
# Notes from the setup (what did NOT work):
#  - onnx-tf (old plan): unmaintained, not used.
#  - onnx2tf -tb tf_converter: fails on MobileNetV2 (layout error at a Conv) -> do not use.
#  - onnx2tf -odrqt / -oiqt outputs: dynamic-range model was broken (~1.5% acc), strict int8 unsupported (FILL op);
#    -> quantize the FP32 .tflite with ai-edge-quantizer instead (works, see quantize_tflite.py).
#  - onnx2tf float16 output has float16 inputs and does not run on the CPU interpreter.
#  - Put D:\kd-project\.venv-export\Scripts on PATH when running onnx2tf (it calls the onnxsim executable).
